The problem

Load testing usually goes wrong in three places.

Scripts nobody reads

A k6 file lives on one laptop. Few people on the team can say what it does or whether it still matches the product.

Numbers nobody explains

p95, p99, iterations. The output is a wall of metrics, and a run can look fine while every request fails.

One wrong target

A mistyped URL can send real traffic at a server that is not yours, and take it down.

Results people can read

An explanation behind every number.

  • Latency (p95, p99, median), requests per second, error rate, iterations, checks, data received, the HTTP phase breakdown and per-endpoint metrics.
  • An "i" on every number explains it in plain language. A warning appears when failed requests are not watched by any threshold, so a run never quietly passes with 100 % errors.
  • Verdicts are read from k6, never recomputed. Live logs stream while the run is going, with secrets redacted.
  • Every run freezes what was executed. Editing a scenario never rewrites history. Re-run in one click.

Environments and secrets

Set the limits once. Every run respects them.

  • Define staging, production and more, each with ceilings on virtual users and duration.
  • Set allowed time windows. A run must fit entirely inside its window. It is refused, never shortened.
  • Secrets are encrypted and injected as environment variables. The API never returns a value, only the name and dates.

Safety and trust

You can only test what you own. That is enforced, not promised.

Ballast checks a challenge file at your origin before anything runs, and checks it again before every run.

1 · Ephemeral container

k6 runs here

A fresh container for each run. It has no outbound route at all.

2 · Filtering proxy

The only way out

Allows just the host of this run. Then it checks the resolved address itself, so an internal network is never reachable.

3 · Verified target

Your environment

staging.example.test

Ownership proven by a challenge file.

Any other destination is refused: other hosts, private networks and internal addresses.

Proof of ownership

A challenge file at your origin is checked before anything runs, and again before every run.

One run at a time

Only one run per environment, so another test never pollutes your measurements.

Isolated by organization

Strict data isolation per organization, enforced in the database itself.

Hard ceilings

Limits on virtual users and duration that cannot be raised from configuration. Rate limits per person and per organization.

Emergency stop

Admins can stop runs at once. A platform-wide switch stops everything.

Append-only audit log

Who launched, refused, cancelled or approved what, including every refusal.

Network traffic is measured twice, on the wire and as reported by the load generator, so usage can be billed fairly and trusted.

FAQ

Questions people ask first.

Do I need to know k6?

No. You can draw a scenario on a canvas, import a Postman collection, an OpenAPI file, a cURL command or a HAR file, and set pass marks with one click. If you already write k6, paste a plain script instead.

Can I test any URL?

No, and that is on purpose. You can only test a target you prove you own. Ballast checks a challenge file at your origin before anything runs, and checks again before every run.

Could a run ever reach an internal network?

No. The load generator has no outbound route. Its only way out is a filtering proxy that allows the host of that run and checks the resolved address, so private networks stay out of reach.

What happens to my secrets?

They are encrypted and injected as environment variables. The API never returns a secret's value, only its name and dates. Live logs redact them. Imports never copy secrets from your files.

Does a passing run mean everything is fine?

A pass means every threshold you set held. Ballast warns you when failed requests are not watched by any threshold, so a run cannot quietly pass with 100 % errors. Verdicts come straight from k6.

Is run comparison available?

Not yet. It is marked Coming soon on this page. Today every run is saved with exactly what was executed, and you can re-run it in one click.
